## Relevant Context — Do Not Deviate Without Escalation

Source: `insight_engine.md` §3.6 / §4.1 (gate mechanics)
- "Hard gate" and "soft gate" are NOT separate phases. They are the same gate phase with different junction settings: `stop_if_fail` (`true` = halt+record; `false` = record, hold `score_penalty`, continue) and `score_penalty` (reduction applied if a non-stopping gate fails; may be negative or zero). Do not model hard/soft as a type — expose `stop_if_fail` + `score_penalty` as the editable junction fields.

Source: `insight_engine-schema-ddl.md` §1/§2 (junction storage)
- Editable mechanical fields are typed columns: `evaluation_order`, `stop_if_fail`, `score_penalty`. Threshold parameters go into the junction `parameters` JSON column. `phase` lives on the rule, not the junction.

Source: `insight_engine.md` §3.6 / §6.6 (ordering)
- `evaluation_order` orders gates within the gate phase, per strategy. Uniqueness within `(strategy, gate-phase)` is a load check — collisions must be surfaced before save succeeds.

Source: ticket AC
- "Add gate from catalog" inserts a junction row binding an existing gate rule to the strategy. "Remove" deletes only the junction row, never the rule.

Source: `UI-GUIDANCE.md` Part 3a / Part 4
- Tokens only; `var(--bg2)` never on rows/headers/panels. Scores `##.00`. No `$`.

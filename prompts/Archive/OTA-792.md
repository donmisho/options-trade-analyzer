## Relevant Context — Do Not Deviate Without Escalation

**Source: insight_engine.md §6.2 (tables are the source of truth)**
Because the runtime tables — not the spreadsheet — are the source of truth, every change to them must be **attributable**. This audit trail is the attribution mechanism: it is to config edits what the engine's per-rule trace is to evaluations.

**Source: insight_engine.md §6.5 (reload) + OTA-790 (Apply / version stamp)**
Config changes take effect on the next engine load; Apply promotes the draft and produces a version stamp. (Per OTA-790 the comparison stamp is a loadable-hash over in-scope, enabled, draft-excluded rows.) Each audit entry links to the version stamp produced by its change. **Phase 0 confirms the exact field/mechanism OTA-790 emits** — link the audit row to that, do not invent a parallel `config_version`.

**Source: auth-process.md (BFF identity) — Backend-for-Frontend (BFF)**
The actor is the authenticated identity from the BFF session (HttpOnly session cookie; FastAPI is the OIDC confidential client). Read the actor from the existing session dependency the CRUD routes already use — do not add a new auth path.

**Source: architecture-plan.md §2 (Data Isolation Invariant) — AS-BUILT DEVIATION (OTA-792 decision, accepted 2026-06-07)**
~~Every CRUD endpoint that takes a resource ID filters by `user_id`. The audit table carries `user_id`; the query endpoint filters by it; cross-user reads return 404 (not 403).~~

**Superseded by the as-built decision.** The Data Isolation Invariant governs *per-user* resources (e.g. `positions`). Engine config (strategies / rules / junctions) is **OTA-app-global shared infrastructure** edited by admins — not per-user data. A config audit trail that hid each admin's edits from other admins would defeat its purpose ("who changed the shared config?"). Therefore isolation is **by `owner_app_id` ('OTA'), not by actor**: the audit table records `user_id` **for accountability only**, the query endpoints do **not** filter by it (any `require_read` admin sees the full OTA trail), and there is **no cross-user 404** — `/audit/{id}` returns 404 only for a genuinely absent id. This is locked by `test_trail_is_shared_not_actor_filtered`. The deviation was reviewed and accepted in place of the original per-user requirement above.

**Source: architecture-plan.md (Schema Migration Strategy — Alembic, expand/contract)**
The audit table is added via an **expand** Alembic migration (additive, non-breaking). Append-only; no foreign keys into the config tables (soft keys only), consistent with the bronze convention.

**Source: OTA-792 ticket — draft vs Apply**
Preview-only **draft** writes (save-to-draft, per OTA-785/790/791/827) must be distinguishable in the trail from **Apply** (live promotion, OTA-790).

## Relevant Context — Do Not Deviate Without Escalation

**Source: OTA-832 build report — validator split + ordering (verified in 832's harness).**
- `init_engine_runtime` (`engine_runtime.py:528-531`) calls `load_config` then `validate_and_raise`. `load_config` runs `_validate_expressions` (a **hard raise**) before returning, so the **loader raise pre-empts the §6.6 validator**.
- `validate_expression` (`expressions.py`) now **short-circuits to valid when the row is a `formula:<name>` ref**, before the §6.3 closed-set check. Formula *existence* is enforced **downstream by `validation.py` (contract / live-registry / drift)** — that is the surface OTA-816 must satisfy.
- Consequence for this Story: until the keystone (OTA-836) retires/canonicalizes the 5 loader-blocking carve-outs, `load_config` still raises and `validate_and_raise` never runs. **A clean live engine load is therefore NOT an achievable OTA-816 acceptance criterion.** OTA-816 is proven by the in-memory harness against `validation.py`'s contract/drift checks — the same harness pattern 832 used.

**Source: OTA-832 build report — what 832 did to the five spec'd names.**
- `credit_pct_of_width_floor`, `debit_pct_of_width_ceiling` → canonicalized to **`BETWEEN` token rules** over existing named values (832 Group A). **Not `formula:<name>` refs → do NOT belong in `('SHARED','formula_registry')`.**
- `dte_warning_penalty` (rule_key `adj_dte_8_13_penalty`) → left as a **carve-out: needs a `formula_ref` with NO live implementation.** Seeding a registry row for it now would create **reverse drift** (registry asserts a formula the code lacks). **Owned by the keystone**, which writes impl + `formula_ref` + seed together.
- `negative_ev_gate`, `dte_hard_filter` → **not named in 832's canonicalization groups and not among the 5 carve-outs.** Their nature (live `formula_ref` vs. already-canonical token rule) is unconfirmed → **Phase 0 must classify.**

**Source: `insight_engine.md` § 6.6 (Startup validation).** The loader rejects config if *a condition expression references a named formula not in the registered rule library* (among other checks). The contract/live-registry/drift form of this lives in `validation.py`.

**Source: `insight_engine-schema-ddl.md` § engine_lookups (lines ~133–150).** Formula-registry membership is a `SHARED` lookup set:
- `engine_lookups(owner_app_id, lookup_set, lookup_key, payload, sort_order, enabled, created_at)`; unique key `(owner_app_id, lookup_set, lookup_key)`.
- `owner_app_id = 'SHARED'` is an FK-enforced sentinel row in `engine_apps`, not a nullable column.
- `payload` is `nvarchar(MAX)` and **must pass `ISJSON(payload) = 1`**; use a JSON object matching sibling rows.
- The `('SHARED','formula_registry')` set is built by `build_formula_registry()` in `scripts/seed_engine_config.py` (runs after `canonicalize_expressions()` in `main()`).

**Source: `insight-agent-migration-plan.md` S2.9 (Named formula registry).** "Document every `formula:<name>` reference used in the rules table. The list is the contract for F4's rule library — every name must have a registered implementation when the engine loads." This list is the **documented contract** OTA-816 reconciles.

**Source: memory / project principle — keep-stopgap.** OTA-816 is **additive reconciliation only**. It does not delete, rewrite, or relocate any formula implementation, does not remove any legacy inline-gate path or shim (e.g. the `OTA-830` step-6d try/except that swallows the dark-engine state), and does not write any missing implementation. Such work belongs to the keystone / cutover.

**Source: `CLAUDE.md` § SoT Documents.** Claude Code modifies SoT docs only when a prompt explicitly instructs it. This prompt authorizes the contract-doc edit below. On any `claude_context/` edit, update the `Last Updated` header (`yyyy-mm-dd hh:mm UTC`) and add an OTA-816 Change Log entry.

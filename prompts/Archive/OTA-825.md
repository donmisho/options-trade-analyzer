## Relevant Context — Do Not Deviate Without Escalation

**Source: OTA-823 (admin list endpoint — sibling pattern) + `insight_engine.md` §6.5**
This endpoint is the rules-side sibling of OTA-823's `GET /api/v1/config/strategies/admin`. It reads **live DB state** via the app's async session — the *current* table truth — NOT the hydrated runtime projection (which is restart-gated, §6.5). It must surface rows the running engine has not yet picked up. Mirror OTA-823's `list_strategies_admin()` shape, session usage, and owner-scoping approach exactly.

**Source: `insight_engine-schema-ddl.md` §1 (app-scoped identity + SHARED sentinel)**
Rules are owned by `owner_app_id = 'OTA'` or the `SHARED` sentinel (cross-app rule library). "Owner-spanning" = return **both** `OTA` and `SHARED` rows. Confirm the exact SHARED sentinel value in §1 during Phase 0; do not hardcode a guessed value.

**Source: `insight_engine-schema-ddl.md` §2 (engine_rules row shape)**
Each returned row carries the full table-row shape: `rule_key`, `owner_app_id`, `phase`, `tier`, `intent`, `referenced_named_values`, `formula_ref`, `parameter_schema`, `null_semantics`, `enabled`. Confirm the actual column names against the migration/DDL in Phase 0 before serializing.

**Source: `insight_engine.md` §6.3 / §6.6 (formula registry + load-time validation)**
A rule's `formula_ref` must resolve to a registered formula or the config fails to load; an unregistered `formula:<name>` is a load-time validation failure. The catalog must show whether each rule's formula is currently registered, so per row compute `formula_registered = registry.has(<name>)` against the **live** `FormulaRegistry`. The frontend cannot derive this — it must come from the backend.

**Source: keystone invariant (this session's locked decision)**
The runtime loader stays on `enabled=1` and is **not touched** by this work. This admin endpoint is a *separate* read path: it applies **no `enabled` filter** (it must return disabled rows so the catalog can show them as unavailable). `AzureSqlConfigSource` (the in-process, `enabled=1`-filtered, restart-gated runtime reader) must remain unchanged — grep-confirm it gains no new behavior.

**Source: OTA-782 Phase 0 finding**
Data access is raw async SQL via `app.models.session.async_session` (the app's async SQLAlchemy factory). There are **no ORM models** for `engine_*` (Alembic is the sole schema authority). The `app/database.py` named in older stale file lists **does not exist** — do not import it.

## Relevant Context — Do Not Deviate Without Escalation

**Source: insight_engine.md §3.6 (Rule phase and gate mechanics)**
- "Hard gate" and "soft gate" are **not** separate phases — they are the same `gate` phase with different junction settings. A gate's failure behaviour is fully described by two junction fields: `stop_if_fail` (true = halts the candidate; false = recorded, candidate keeps scoring) and `score_penalty` (reduction applied on a non-stopping fail; may be negative or zero). The Hard Gates tab edits gate-phase junction rows; it does not invent a separate "hard/soft" type.
- Each gate carries an `evaluation_order` per strategy. Gates run cheapest/most-decisive first; a `stop_if_fail=true` gate that fails halts evaluation, so order matters. The tab must expose `evaluation_order` as editable.

**Source: insight_engine.md §6.1 (Three-table model) + insight_engine-schema-ddl.md §2**
- Per-rule configuration for a strategy lives **only** in the junction row. The OTA-826 read returns the full junction shape: `junction_id`, `strategy_id`, `rule_id`/`rule_key`, `evaluation_order`, `stop_if_fail`, `score_penalty`, `weight`, `parameters` (JSON), `terminal_verdict`, `rationale`, `enabled` — plus joined rule display metadata (`phase`, `intent`, `parameter_schema`). `phase` lives on the **rule**, not the junction. Render labels from the joined metadata; do not make a second call.
- Threshold parameter edits write into the junction `parameters` JSON column (one object, not per-parameter columns).

**Source: insight_engine.md §6.6 (Startup validation) + OTA-783 + OTA-826**
- The authoritative `evaluation_order` uniqueness check (within strategy + rule.phase) is a **pre-existing server check** — `validation.py::_check_eval_order_uniqueness` / `EVAL_ORDER_DUPLICATE` — enforced at engine load. **OTA-826** added the junction read endpoint and the §6.6 doc-parity entry; it did **not** add or modify the check. **Save-time** enforcement is **OTA-783** (uniqueness is among its save checks), which rejects a colliding write to the draft key; engine load is the backstop. Do not reimplement the uniqueness rule as a client-authoritative gate, and do not claim "collisions are surfaced before save succeeds" — OTA-783 (at save) and load-time validation are the source of truth.

## Relevant Context — Do Not Deviate Without Escalation

**Source: insight_engine.md §2, Principle 2 (Strategy independence)**
"No `if strategy_id == X` branches anywhere in engine code." Strategies are routed by config lookup only. No shared per-family scorer functions, no cross-strategy fallback, no shared mutable state.

**Source: insight_engine.md §4 (Pipeline)**
A pipeline run takes a stream of candidates, **a strategy id**, and a `source_app_id`, and runs fixed-order phases (gates → scoring → adjustments → verdict), rules within a phase in junction `evaluation_order`. The orchestrator is the only execution path. Each strategy scores through this one pipeline over its own junction rows — there is no per-family scoring function.

**Source: insight_engine.md §3.4 (Junction-only invariant)**
A strategy's per-rule configuration lives only in its junction rows. There is no fallback to "what the rule says."

**Source: OTA-695 (Engine core, Code & Test Complete) + OTA-725 (Screening rule library, Code & Test Complete)**
The engine pipeline and the registered screening formulas already exist and are committed. SP/WG/TR/LT scoring criteria are registered formulas the engine resolves via `formula:<name>`. This story routes each strategy *into that pipeline*; it does not create new formulas.

**Source: OTA-695 scope anchor**
The legacy `VerticalSpreadEngine` / `NakedOptionEngine` internal weight sets are **superseded** — per-strategy junction weights are the sole weighting mechanism (resolved to delete, not codify).

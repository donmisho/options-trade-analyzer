## Relevant Context — Do Not Deviate Without Escalation

**Source: insight_engine.md §3.3 (rule fields) + §6.1 (rules table)**
A rule carries: `rule_id`, `phase` (gate / scoring / adjustment), `tier` (RAW / DERIVED / COMPUTED), `condition_expression`, `referenced_named_values` (inputs), `parameter_schema`, `intent`. Rules are independent of any strategy — a rule is bound to a strategy only by a junction row.

**Source: insight_engine.md §6.3 (expression library) + §6.6 (startup validation)**
A condition expression may reference a named formula as `formula:<name>`; the engine looks it up in the registered rule library. Startup validation rejects the configuration if a condition references a `formula:<name>` not in the registered library. The browser surfaces, per rule, **whether that rule's `formula:<name>` has a registered implementation** (the "formula-registry status").

**Source: insight_engine-schema-ddl.md §1 (app-scoped identity)**
`engine_rules` use a surrogate `INT` PK plus a natural key `(owner_app_id, rule_key)`. The cross-app library is `owner_app_id = 'SHARED'`; OTA content is `'OTA'`. The browser shows **both**. SHARED rules are selectable for binding (a junction row may reference them) but are **read-only** — no edit or delete of the rule itself from this surface.

**Source: OTA-789 ticket — single rule source**
This browser is the **single** source for the "Add from catalog" pickers used by the Hard Gates (OTA-785), Scoring (OTA-786), and Adjustments (OTA-787) tabs. Rules are filterable by phase so each tab's picker shows only phase-compatible rules. There is no separate rule list feeding the pickers.

**Source: CLAUDE.md → House Style + UI-GUIDANCE.md**
Dark-theme CSS variables only (from `web/src/styles/tokens.js`) — never inline hex. No `$` on any value. Numeric display per house style (`##.00` scores, `##.00%` probabilities/IV rank, `##%` config percentages). Buttons sized to content. The prototype catalog drawer is the layout contract.

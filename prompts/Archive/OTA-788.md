## Relevant Context — Do Not Deviate Without Escalation

Source: `insight_engine.md` §3.8 (verdict bands)
- A verdict band set is a **monotonic** mapping from final adjusted score to a categorical verdict, defined **per strategy**. The engine treats labels as opaque strings. Screening uses `EXECUTE/WAIT/PASS`; health grading uses `A/B/C/D/F` — which one depends on the strategy's `consumer_surface`/`candidate_type`.

Source: `insight_engine.md` §6.6 (monotonicity is a load check)
- A non-monotonic band set fails engine load. The editor flags non-monotonic ordering before save, consistent with the loader check.

Source: `insight_engine-schema-ddl.md` §2 (storage)
- Bands live in `engine_strategies.verdict_band_set` (`NVARCHAR(MAX)` JSON, `NOT NULL`, `ISJSON=1`). Saves write the whole band set via CRUD (OTA-782) against the draft.

Source: `insight_engine.md` §3.8 + OTA-761 / OTA-773
- Per-strategy bands replaced the hardcoded universal 70/50 thresholds. **No verdict band threshold may remain hardcoded** in app/UI code — the literals OTA-761 removed do not return.

Source: `UI-GUIDANCE.md` Part 3 / Part 4
- Verdict badge colors: EXECUTE → green, WAIT → amber, PASS → red. Health grades: A=green, B=teal, C=yellow, D=orange, F=red. Scores `##.00`. Tokens only; `var(--bg2)` never on rows/panels.

## Scope
Build the Verdict Bands editor: render the selected strategy's `verdict_band_set` (screening bands or health grades per `candidate_type`) with editable thresholds and labels; enforce monotonic ordering with a pre-save flag; persist the whole set to `verdict_band_set` via CRUD against the draft. No hardcoded thresholds.

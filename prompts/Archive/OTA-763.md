## Relevant Context — Do Not Deviate Without Escalation

**Source: `insight_engine.md` §8 — engine boundaries.**
"presenting results (the consumer's UI renders the result record)" is the consumer's job, not the engine's. The UI renders **what the engine decided**. No score or verdict is re-derived in the UI.

**Source: `insight_engine.md` §4.2 — result record.**
The result record carries: final adjusted score, verdict, the terminal phase (where the candidate exited — halted at a gate, or completed through verdict), and the **mandatory full per-rule trace** (per-gate, per-criterion, per-adjustment results with decision reasons). The UI reads these fields directly for verdict cards, scorecards, and the diagnostic panel.

**Source: ticket OTA-763 — halt vs band verdict.**
Halt-verdict cases (e.g. `WAIT_FOR_EARNINGS`) must render distinctly from a band-assigned `WAIT`, using the `verdict_source` discriminator. **Confirm the exact field name in Phase 0** — it is either `verdict_source` or `terminal_phase` per the §4.2 record; render off whichever the deployed `ResultRecord` actually carries.

**Source: `CLAUDE.md` House Style + `UI-GUIDANCE.md` — formatting contract.**
- Scores (0–100): `##.00` everywhere — inline row, expansion panel, total row.
- No `$` prefix on monetary values; monetary `##.00`; probabilities `##.00%`; dates `mm-dd-yyyy` via `formatDate()`.
- Dark-theme CSS variables only (from `web/src/styles/tokens.js`); never inline hex.
- `var(--bg2)` (#161b22) restricted to filter bars, QuoteBar, pill badges only — never table rows, headers, or expansion panels.
- Buttons sized to content, never full-width unless explicitly designed; visible border/background in default state.

## Relevant Context — Do Not Deviate Without Escalation

Source: `insight_engine-schema-ddl.md` §1 (App-scoped identity)
- `engine_rules`, `engine_strategies`, `engine_lookups` each have a surrogate `INT IDENTITY` PK **plus** a natural key `(owner_app_id, <key>)`. The cross-app rule library is `owner_app_id='SHARED'`; OTA content is `owner_app_id='OTA'`. `SHARED` is a sentinel row in `engine_apps`, never a nullable column.

Source: `insight_engine-schema-ddl.md` §2 (natural-key uniqueness)
- `UQ_engine_rules_owner_key (owner_app_id, rule_key)`, `UQ_engine_strategies_owner_key (owner_app_id, strategy_key)`, `UQ_engine_lookups (owner_app_id, lookup_set, lookup_key)`, `UQ_engine_junction (strategy_id, rule_id)`. Duplicate-key writes must surface a clear conflict error, not a 500.

Source: `insight_engine-schema-ddl.md` §1 (Junction parameter storage)
- Mechanical junction fields are typed columns: `evaluation_order`, `stop_if_fail`, `score_penalty`, `weight`, `enabled`, `rationale`. Variable per-rule parameters go in the single `parameters NVARCHAR(MAX)` JSON column — **not** per-parameter columns. `ISJSON(parameters)=1` is enforced by `CK_engine_junction_params`.

Source: `insight_engine-schema-ddl.md` §2 (phase placement)
- `phase` lives on `engine_rules`, not on the junction. The junction binds a rule to a strategy; the rule's phase determines gate/score/adjustment behavior.

Source: `insight_engine.md` §6.2 (tables are the source of truth)
- These tables are the runtime source of truth. Writes here change what the engine loads at next start (§6.5) — this API is the durable maintenance surface that replaces spreadsheet edits.

Source: ticket AC + `auth-process.md`
- Every write stamps/forces `owner_app_id='OTA'`. Any request that targets a `SHARED` row (rule-library or SHARED lookup set) is rejected — no SHARED mutation is possible through this API. All endpoints are session-authenticated through the BFF; no anonymous config mutation.

## Scope
Add the config **write** side — `POST` / `PUT` / `DELETE` over `engine_strategies`, `engine_rules`, `engine_strategy_rule_junction`, and `engine_lookups` — extending the OTA-762 read endpoint family (`/api/v1/config/...`). Return the same canonical shape OTA-762 reads. All writes are app-scoped to `owner_app_id='OTA'`; SHARED rows are read-only through this API. Junction per-rule parameters are written into the validated `parameters` JSON column.

This story is the write transport only. The save-time validation that mirrors engine load is OTA-783 (next prompt) — wire a clear seam for it but do not implement the validation rules here.

## Acceptance criteria
- CRUD endpoints exist for strategies, rules, junction rows, and lookups, each returning the canonical OTA-762 shape.
- Every write stamps/forces `owner_app_id='OTA'`; a request targeting a `SHARED` row is rejected (verified by test).
- Natural-key uniqueness is respected; a duplicate key surfaces a clear conflict response (e.g. 409), not a 500.
- Junction per-rule parameters persist to the `parameters` JSON column; mechanical fields persist to their typed columns.
- All endpoints are BFF-session-authenticated; an unauthenticated request is rejected.

## Out of scope

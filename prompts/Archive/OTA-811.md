## Relevant Context — Do Not Deviate Without Escalation

**Source: `insight_engine-migration-plan.md` § S9.6 (the rename spec) + glossary**
- The existing `app/agents/insight_engine.py` is the **Claude-based observation→insight Communicator** — it turns detected anomalies/verdicts into human-readable insights. With the new *generic* Insight Engine taking the "Insight Engine" name, the existing component is renamed to the **Insight Communicator**.
- Exact rename map:
  - `app/agents/insight_engine.py` → `app/agents/insight_communicator.py`
  - Class `InsightEngine` (if it exists) → `InsightCommunicator`
  - Skill dir `app/skills/insight-engine/` → `app/skills/insight-communicator/` (including everything under it, e.g. `domains/options/SKILL.md`)
- The `insights` **table name is unchanged** — it stores Communicator output (rightly called insights). Do not touch the table, its model, or its `domain='options'` writes.

**Source: `insight_engine.md` Change Log v2.2 (2026-05-21) — naming collision, resolved**
- Canonical decision: the *new framework* is the **Insight Engine**; the *existing* `app/agents/insight_engine.py` is renamed **Insight Communicator**. The two are distinct components.

**Source: `architecture-plan.md` §5 / Pattern 5 + agent inventory (current state)**
- The Communicator is invoked by the **Position Monitor Agent** (`app/agents/position_monitor.py`) on threshold crossings / deviations. The Position Monitor's escalation logic **stays in the agent** — this story only renames the callee, it does not move escalation logic.
- The Communicator loads a generic system prompt from `app/skills/insight-engine/SKILL.md` and a domain template from `app/skills/insight-engine/domains/options/SKILL.md`, validates against the `Insight` Pydantic schema, and writes to `insights`. After this rename those two skill paths live under `app/skills/insight-communicator/`.

**Source: project convention — `skill_loader.py`**
- `skill_loader.py` builds skill paths as `app/skills/{skill_name}/SKILL.md`. The skill folder rename therefore also requires changing the `skill_name` **string argument** passed at the Communicator's load call site(s) from `"insight-engine"` to `"insight-communicator"`. A folder `git mv` alone is not sufficient — the string that names the skill must change too, or the loader will 404 at runtime.

**Source: OTA-811 acceptance text**
- Final gate: `grep -r "insight_engine" app/agents/` returns **no hits except legitimate references to the new generic engine package**. This implies a generic engine package exists whose name/path may legitimately contain `insight_engine`. You must identify that package in Phase 0 so you can distinguish a *legitimate* reference (leave it) from a *stale* one (rename it).

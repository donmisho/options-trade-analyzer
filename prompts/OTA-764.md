## Relevant Context — Do Not Deviate Without Escalation

**Source: OTA-764 ticket body (scope) + `insight_engine-migration-plan.md` §S5.7, §S11**
The Position Monitor Agent currently grades open positions via a **Claude batch call**: `position_monitor.py` calls `_adapter.chat(...)`, parses `PositionHealthUpdate.health_grade` from the returned JSON, and `_apply_updates` writes `pos.health_grade`. There is **no** direct `app/analysis/health_grade.py` call in the agent (the old "replace the direct health_grade.py call" premise is stale — confirmed by 764 Phase 0). This story replaces that **Claude grading path** with a single engine call.

**Source: OTA-764 ticket body — per-position flow**
For each open position the agent must:
1. Check `position_exit_levels_complete` (published by the position-health adapter, OTA-734).
2. Select strategy: `position_health_full` when complete, `position_health_basic` otherwise.
3. Call `engine.evaluate(candidates=[position_candidate], strategy_key=<selected>, source_app_id="OTA")` against the position-health adapter/runtime.
4. Write the result record's verdict letter (`record.verdict`, A–F via `BAND_LOOKUP`) to `positions.health_grade`. The full per-rule trace is persisted by the engine sink (OTA-758) — the agent does **not** write the trace.
5. Preserve existing alert/insight escalation — on threshold-crossing verdicts invoke the Insight Communicator (`app/agents/insight_communicator.py`). **Escalation logic stays in the agent.** The engine produces verdicts; the Communicator produces prose.

**Source: `insight_engine.md` §2 (principle 2.1 single path) + §2.6 (LLM precedence)**
There is exactly one evaluation path — the engine. No parallel verdict-assignment path may remain in the agent after this story. The deterministic engine evaluation must run to completion **before** any LLM/Communicator call; the Communicator only ever elaborates on an already-computed verdict, it never discovers grade.

**Source: `insight_engine.md` §4.3 + §6 (fail-closed)**
`engine.evaluate(...)` raises if the requested `strategy_key`/surface is not seeded — it never substitutes a default. The agent must let that raise (fail closed), not catch-and-fallback to the old Claude path.

**Source: OTA-764 prerequisite (now satisfied)**
POSITION_HEALTH is seeded into the live `engine_*` tables and included in `build_combined_registry()` (OTA-844, on `main`). The adapter (OTA-734) and rule library (OTA-742) are deployed. Phase 0 must confirm the seed is present in the working branch before proceeding.

**Source: `insight_engine-migration-plan.md` §S11 (strategy preconditions)**
`position_health_full` additionally requires `position_exit_levels_complete = true` and `position_structure_direction` in (bullish, bearish). `position_health_basic` uses P&L alone. Strategy selection is **orchestration** (the agent picks per position); the engine evaluates whichever strategy it is handed.

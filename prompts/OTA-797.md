## Relevant Context — Do Not Deviate Without Escalation

Source: `insight_engine.md` §6.6 (startup validation — the failure modes to cover)
The loader rejects config with a loud, structured error if any hold:
- a rule references a named value not in the input catalog
- a junction row references a rule_id or strategy_id that does not exist
- a junction row does not supply every parameter in the rule's schema
- a gate junction row omits `evaluation_order` or `stop_if_fail`
- a strategy's active scoring criteria weights do not sum to 1.0 (within documented tolerance)
- a verdict band set is not monotonic
- a condition expression references a `formula:<name>` not in the registered rule library
- a junction parameter value violates the rule's parameter type or bound
- a named value's null semantics are incompatible with the rule's needs

Source: OTA-797 acceptance criteria (additional explicit cases)
Also cover: the **three** formula-registry error paths separately — missing from the **contract**, missing from the **registry**, and **drift** between them; `evaluation_order`-uniqueness **within (strategy, phase)**; `terminal_verdict` outside its domain; duplicate `evaluation_order`; unknown `terminal_verdict`. Plus a **valid** config fixture that loads cleanly (negative control).

## Scope

Build a systematic config-validation test matrix (new module, e.g. `tests/insight_engine/test_config_validation_matrix.py` — confirm path in Phase 0): one fixture per §6.6 failure mode (plus the OTA-797 additions above), each asserting the loader rejects the bad config with its **specific** structured error identity, and one valid fixture that loads cleanly.

## Acceptance criteria

* Each §6.6 failure mode has a fixture the loader rejects with its specific structured error identity.
* The three formula-registry error paths (missing from contract, missing from registry, drift) are each exercised separately.
* `evaluation_order`-uniqueness-within-(strategy, phase) and `terminal_verdict`-domain rejections are present.
* Type/bound violation, junction-completeness, gate-row `evaluation_order`/`stop_if_fail` omission, weight-sum ≠ 1.0, non-monotonic bands, unknown named value, and missing rule/strategy reference each have a fixture.
* A valid config fixture loads cleanly (negative control).
* Assertions match the live loader's error identities (no parallel validator).

## Relevant Context — Do Not Deviate Without Escalation

**Source: insight_engine.md §3.4 (Strategy entity) + §6.1 (three-table model)**
A strategy header (`engine_strategies`) carries only: `strategy_id`, `label`, `verdict_band_set`, `scan_parameters` (engine knobs — eval cap, output cap), and `description`. It does **not** carry per-strategy scalar gate thresholds.

**Source: insight_engine.md §3.4 (junction) + §3.6 (gate mechanics) + insight_engine-schema-ddl.md (`engine_strategy_rule_junction`)**
Per-strategy gate thresholds (DTE min/max, short-delta max, IV-rank min, credit/width, debit/width) live in `engine_strategy_rule_junction.parameters` — a single JSON column, validated at engine load against the rule's `parameter_schema`. The junction is the *only* home of a strategy's configuration for a rule. **Junction-only invariant:** there is no fallback to "what the rule says"; a missing required parameter is a startup-time validation failure. There is no separate "parameters" entity in the model.

**Source: OTA-827 ticket — Phase 0 hard data-model question**
The card set straddles two backing stores:
- **DTE range is already a strategy header field (OTA-784).** It must **NOT** be duplicated. Either drop DTE from this section, or bind the DTE card(s) to the *same* header field (single source of truth). The prototype's `syncDteFromParams()` two-store sync pattern is exactly what we are NOT doing.
- **Delta / IV-rank / credit-width thresholds** look like `parameters` JSON keys on specific **gate junction** rows.

No new "parameters" concept that duplicates header or junction state. **If a card has no valid backing store at current HEAD, drop the card and report it — do not invent a store to host it.**

**Source: OTA-827 ticket — reuse, not reimplement**
Reuse OTA-785's shared param-editor subcomponent and its junction client methods. Reuse the OTA-784 editor-shell `SECTIONS` slot mechanism. Writes are **save-to-draft** (target the draft key), consistent with OTA-785 / OTA-790 / OTA-791. Saves route through the OTA-782 CRUD API and OTA-783 validation. No second param-editor implementation; no second client path.

**Source: CLAUDE.md → House Style Rules + UI-GUIDANCE.md**
- No `$` anywhere in the UI.
- Scores (0–100): `##.00`. Monetary: `##.00`.
- Probabilities and IV rank: `##.00%`.
- Config percentages: `##%` (no decimals).
- Dates: `mm-dd-yyyy` via `formatDate()` from `web/src/utils/formatDate.js`.
- Dark-theme CSS variables only, from `web/src/styles/tokens.js` — never inline hex.
- Buttons sized to content, never full-width; visible border or background in default state.

**Source: insight-agent-migration-plan.md v4 (acceptance reframe)**
Acceptance for the Completion effort is **functional, not parity** — render the engine's config correctly and write it through the correct path. Card values, types, and formatting are what matter here; verdict values are out of scope for this story.

## Relevant Context — Do Not Deviate Without Escalation

Source: `insight_engine.md` §4.2 (mandatory full trace)
Every rule evaluation in a run appears in the result-record trace — **including non-stopping gate failures and zero-penalty decisions**. Without the full trace the engine is unauditable against the tables. This is a required property of the result record, not an optional diagnostic.

Source: `insight_engine.md` §4.3 (two **logical** streams) + `insight_engine-schema-ddl.md` §3 (one **physical** table) — RECONCILE
The engine builds two logical record streams per run: **candidate snapshots** (one per candidate per run) and **evaluation decisions** (one per rule evaluation). NOTE THE DISCREPANCY: §4.3 sketches these as two physical tables (`candidate_snapshots`, `evaluation_decisions`); the **authoritative physical schema is `insight_engine-schema-ddl.md` §3** — a **single** `bronze_evaluations` table discriminated by `record_type` ('SNAPSHOT' / 'DECISION'), with a `bronze_payload_contract` entry per `(record_type, discriminator_value, payload_version)`. Assert against the **single-table** shape. If the live sink (OTA-758) does not match schema-ddl §3, STOP and report — do not adapt the test to a non-conforming sink.

Source: `insight_engine.md` §1 + §4.3 (provenance stamping)
Every persisted record carries `source_app_id` (='OTA' for this consumer), the run's `config_version`, and `evaluated_at`. Snapshot↔decision correlation is by shared `snapshot_id` / `run_id` — bronze has **no FKs**.

Source: OTA-758 (sink semantics)
The sink is fire-and-forget bronze persistence invoked **inside** `engine.evaluate`, not in the route. Bronze write is **additive** audit — it never replaces operational persistence. Tests run trace-shape assertions against the **in-memory** sink and persisted-shape assertions against the **real** sink (OTA-758).
